- 2026-02-26 — New T4 architecture direction: move from a depth-based content model toward a recursive tree classification (`root` special case; `entry` = folder containing blocks; `collection` = folder containing subfolders and no blocks; folders inside entries remain folder blocks). Empty folders outside entries are ignored with a non-blocking informational warning, and non-core root files are ignored. Reason: better match Webette’s filesystem-first promise while enabling nested collections + root entries with a single coherent model.
- 2026-02-26 — The T4 refactor must preserve the final rendered output of `website-example` (non-regression target), even if internal model/export structures evolve. Reason: architectural change should not break the current reference site behavior during beta preparation.

Reason: complete the T4 architecture shift while keeping compatibility views for consumers without preserving the previous internal calculation path.
- 2026-02-26 — ArPiDoc user-facing documentation must describe the current recursive model as the product behavior, without framing features through older internal methods or migration-era wording. Reason: Webette is not publicly released yet, so product docs should explain how it works now, not internal implementation history.
